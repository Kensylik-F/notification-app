# notifications-kit

Клиент сервиса уведомлений и интерфейс поверх него: колокольчик, лента,
просмотр уведомления, объявления (баннеры), а для модераторов — рассылки,
история доставок и публикация объявлений. Версия 0.4.2.

Папка самодостаточна: её можно перенести в проект целиком. Внутри нет
импортов из приложения, HTTP-клиента и UI-библиотек.

Зависимости, которые должны быть в проекте:
`react` 18, `react-dom` 18, `@tanstack/react-query` 5, `zod` 4.
Сборщик должен понимать CSS-модули (`*.module.css`).

## Устройство

```
core/      контракт, клиент, ошибки, повторы, OData — без React
  generated/   схемы и таблица операций, собраны из OpenAPI; руками не править
react/     провайдер, хуки, компоненты, стили
```

## Подключение

### 1. Транспорт

Кит не делает запросы сам. Ему передают функцию, которая выполняет один
запрос и **возвращает ответ при любом статусе**: по телу ошибки кит читает
стабильный `code`. Перехватчик, который превращает 4xx/5xx в исключение или
переписывает тело, для этой функции не подходит — нужен отдельный экземпляр
клиента.

```ts
import axios from 'axios';
import type { NotificationsTransport } from '@/lib/notifications-kit';

const http = axios.create({
  baseURL: '/api/notifications', // префикс, под которым сервис стоит за шлюзом
  validateStatus: () => true, // статус разбирает кит
});

export const transport: NotificationsTransport = async request => {
  const response = await http.request({
    method: request.method,
    url: request.path, // '/api/v1/inbox/…' — путь из контракта
    params: new URLSearchParams(request.query.map(([k, v]) => [k, v])),
    headers: request.headers,
    data: request.body,
    signal: request.signal,
  });
  return {
    status: response.status,
    headers: response.headers as Record<string, string>,
    data: response.data,
  };
};
```

Если запрос не дошёл (сеть, таймаут, отмена), функция должна выбросить
исключение — как это и делает axios.

### 2. Провайдер

```tsx
import {
  AnnouncementsHost,
  NotificationsProvider,
  createNotificationsApi,
} from '@/lib/notifications-kit';

const api = createNotificationsApi({
  transport,
  acceptLanguage: () => i18n.language,
});

<QueryClientProvider client={queryClient}>
  <NotificationsProvider
    api={api}
    locale='ru'
    enabled={isSignedIn}
    features={{ inbox: false, mailings: false }}
    storageScope={user.id}
  >
    <App />
    <AnnouncementsHost />
  </NotificationsProvider>
</QueryClientProvider>;
```

`api` и функции, передаваемые в провайдер, создаются один раз (вне
компонента или через `useMemo`/`useCallback`).

**Части кита — `features`** (по умолчанию всё включено). Выключенная часть
не рисуется и **не делает запросов** — так её включают и выключают
флагами приложения:

| Ключ            | Что включает                                                                         |
| --------------- | ------------------------------------------------------------------------------------ |
| `bell`          | `NotificationBell`                                                                   |
| `announcements` | Объявления: запросы `/announcements`, вкладка, строки в колокольчике                 |
| `banners`       | Показ объявлений поверх страницы (`AnnouncementsHost`); требует `announcements`      |
| `inbox`         | Входящие: запросы `/inbox`, вкладка, строки и счётчик в колокольчике, карточки новых |
| `mailings`      | `NotificationComposer`, `DeliveryLog`                                                |
| `publishing`    | `AnnouncementPublisher`                                                              |

`enabled={false}` выключает всё сразу (например, пока пользователь не загружен). `storageScope` — id
пользователя: под ним кит хранит в браузере историю закрытых объявлений,
чтобы она не смешивалась у разных людей на одном компьютере.

### 3. Компоненты

| Компонент                                                   | Что это                                                                                                                | Основные пропсы                                                          |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `NotificationBell`                                          | Кнопка в шапке: счётчик; в списке объявления, просмотренные, входящие                                                  | `anchorRef`, `onOpenAnnouncement`, `onOpenItem`, `onOpenAll`, `limit`    |
| `NotificationCenter`                                        | Страница уведомлений: вкладки «Входящие» и «Объявления», слева список, справа текст выбранного                         | `tab`, `selectedId`, `unreadOnly` (+ `on…Change`), `onOpenItem`, `title` |
| `InboxActions`                                              | «Прочитать все» и «Закрыть все» — для шапки страницы                                                                   | —                                                                        |
| `MarkAllReadButton`, `DismissAllButton`, `InboxList`        | Те же части по отдельности                                                                                             | —                                                                        |
| `InboxItemView`                                             | Одно уведомление (то же, что справа в `NotificationCenter`; для страницы по прямой ссылке)                             | `id`, `onDismissed`, `onOpenSeparately`, `showSubject`                   |
| `AnnouncementsHost`                                         | Всё, что появляется поверх страницы: объявления, карточка нового уведомления, предпросмотр из форм. Один на приложение | `onOpenItem`, `onOpenAnnouncement`, `inboxToasts`                        |
| `Tabs`, `Switch`, `Button`, `CloseButton`, `Dialog`, `Chip` | Примитивы кита — чтобы вкладки и кнопки страницы выглядели так же                                                      | —                                                                        |

Навигации в ките нет: куда вести по клику, решает приложение через
`onOpenItem` и `onOpenAll`.

**Страница уведомлений — `NotificationCenter`.** Одна строка вкладок:
«Входящие N» и «Объявления N»; справа в ней — переключатель «Только
непрочитанные». Слева список (точка у непрочитанного, тема, время, первая
строка текста), справа выбранное уведомление целиком: тема, дата, «Важное»,
HTML-текст, «Закрыть» и значок «Открыть на отдельной странице» (если
передан `onOpenItem`). Открытие отмечает уведомление прочитанным
(`POST …/read`). После «Закрыть» строка уезжает, открывается следующая.
Уже `720px` по ширине — список и текст сменяют друг друга, с кнопкой «К
списку». Вкладку, выбранное и фильтр можно держать в адресе:
`tab`/`onTabChange`, `selectedId`/`onSelectedChange`,
`unreadOnly`/`onUnreadOnlyChange`. С `title` компонент рисует заголовок и
`InboxActions` сам; без него положите `<InboxActions />` в шапку страницы.
Если одна из частей выключена (`features`), вкладок нет — страница сразу
показывает другую.

На вкладке «Объявления» — «Активные» (ответ сервиса, важные сверху) и
«Закрытые ранее» (история этого браузера, см. ниже). У `TRANSACTIONAL` —
красная точка и метка «Важное».

**HTML.** Если сервис прислал `bodyHtml`, кит показывает его сам — в
изолированной рамке (`iframe` без скриптов): стили страницы не ломают
письмо, письмо не ломает страницу, цвет и шрифт текста берутся со страницы,
высота — по содержимому, ссылки открываются в новой вкладке. Свой рендерер
(например, с санитайзером проекта) можно передать в провайдер пропом
`renderHtml` — тогда кит использует его.

**«Закрыть все».** Массового закрытия в API нет. `DismissAllButton` после
подтверждения проходит ленту и закрывает уведомления по одному, по 4
одновременно, с прогрессом и кнопкой «Остановить». Закрытое остаётся
доступным по прямой ссылке. Логика — в хуке `useDismissAll`.

**Колокольчик.** Счётчик — активные объявления плюс непрочитанные
входящие (что из этого включено). В списке: активные объявления (важные
сверху), «Просмотренные» — последние закрытые в этом браузере (`seenLimit`,
по умолчанию 3), «Входящие». Клик по объявлению вызывает
`onOpenAnnouncement`, по уведомлению — `onOpenItem`; приложение открывает
страницу уведомлений с ним. Список
выводится в `<body>` (его не обрежет `overflow` шапки); чтобы его правый
край совпал с краем шапки, передайте ref шапки: `anchorRef={headerRef}`.

**Новое уведомление.** Push-канала у сервиса нет: когда опрашиваемый
счётчик растёт, `AnnouncementsHost` читает новые строки и показывает
карточку «Новое уведомление» в углу на 8 секунд (наведение ставит на
паузу). «Открыть» вызывает `onOpenItem` хоста; без него уведомление
открывается в окне. Выключить — `inboxToasts={false}`.

Строка ленты никогда не показывает сырой код категории: до прихода темы —
подпись из `describeItem`, без неё — «Уведомление».

Хуки для своих компонентов: `useUnreadCount`, `useUnreadBadge`,
`useInboxList`, `useInboxItem`, `useInboxCommands`, `useDismissAll`,
`useAnnouncements`, `useAnnouncement`, `useDismissedAnnouncements`,
`useOutstandingAnnouncementCount`, `useDismissAnnouncement`,
`useKitPreview`.

## Объявления

### Вид показа — по классу

Сервис сообщает, **что** это за объявление (`category` и `categoryClass`,
класс задаёт каталог категорий сервиса), и не имеет поля «как показывать».
По умолчанию кит выбирает вид по классу:

| Класс                   | Вид      | Как выглядит                                                                                | Закрытие                       |
| ----------------------- | -------- | ------------------------------------------------------------------------------------------- | ------------------------------ |
| `TRANSACTIONAL`         | `modal`  | Окно по центру, страница позади слегка размыта; «Понятно»                                   | «Понятно» → `dismiss`          |
| `PLATFORM`              | `toast`  | Полоса сверху по центру; верх страницы за ней размыт до низа полосы. Висит, пока не закроют | «×» → `dismiss`                |
| `MARKETING`, без класса | `corner` | Стопка в правом верхнем углу: новая спереди, две выглядывают. Клик раскрывает списком       | «×», «Закрыть все» → `dismiss` |
| —                       | `none`   | Поверх страницы не показывается, только в колокольчике и на странице                        | —                              |

Свою схему задаёт `resolvePresentation`: `presentationByClass({ PLATFORM:
'corner' })` или `presentationByCategory({ код: вид })` — для перечисленных
категорий, остальные по классу.

### Очередь

Объявления не появляются все сразу:

1. через `firstDelayMs` (1,5 с) после загрузки — окна, по одному, от
   старого к новому (счётчик «1 из N» — `showPosition`, по умолчанию
   выключен);
2. затем полосы — так же по одной;
3. затем стопка — все карточки сразу (без ограничения, `maxCorner`).

Между закрытием одного и появлением следующего — `gapMs` (0,8 с). То, что
уже на экране, остаётся; новое объявление встаёт в очередь по своему
классу. Полоса сама не исчезает (`stripDurationMs` — скрыть по времени до
конца сессии). Предпросмотр из форм модератора идёт мимо очереди.

### Где они появляются

Поверх всего, ни к какому блоку не привязано: окна — по центру, полосы —
сверху по центру (поверх шапки), стопка — в правом верхнем углу. Отступы —
`--nk-overlay-top`, `--nk-overlay-right` (16 px) и `--nk-corner-top` для
стопки (по умолчанию как `--nk-overlay-top`). Чтобы стопка не закрывала
колокольчик, задайте `--nk-corner-top` по высоте шапки. Если на узком окне
полоса и стопка пересекаются, стопка сдвигается вниз.

Клик по карточке или «Подробнее» открывает полный текст в окне с «Больше
не показывать» (`onOpenAnnouncement` — открыть у себя).

### История — «Закрытые ранее»

Сервис отдаёт только **активные незакрытые** объявления, а закрытое
доступно по id лишь до конца срока показа — потом сервис его удаляет.
Списка закрытых и истории в API нет. Поэтому:

- «Активные» — ответ сервиса;
- «Закрытые ранее» — то, что закрыли в **этом браузере**: при закрытии кит
  сохраняет объявление в `localStorage` (до 50, под `storageScope`). Пока
  срок показа не истёк, кит перечитывает объявление из сервиса; после —
  показывает сохранённую копию и пишет об этом.

Полной истории (с любого устройства, после срока показа) без новых
операций в сервисе не будет.

### Анимации

Появление и уход окна (подъём; уход — вниз) и полосы (выезжает сверху,
уезжает вверх вместе с размытием), пульсация значка, появление и уход
карточек, раскрытие и сворачивание стопки (карточки
переезжают на новые места), строка списка, уходящая после «Закрыть»
(остальные смыкаются), подчёркивание вкладок и «бегунок» переключателей,
окна (затемнение и подъём), меню, «Дополнительно» в форме, отметки каналов.
При `prefers-reduced-motion: reduce` всё это отключается.

Встроены словари `ru` и `en`; выбор — по `locale`. Отдельные строки
заменяются пропом `messages`, весь механизм — пропом `translate`. Ключи —
в `react/messages.ts` и `react/admin-messages.ts`.

## Ошибки и повторы

Любая ошибка кита — `NotificationsError` с полем `kind`:

- `problem` — сервис ответил не 2xx; доступны `status`, `code`, `title`,
  `detail`, `traceId`, `retryAfterMs`. Ветвиться нужно по `code`;
- `network` — ответа не было;
- `contract` — ответ 2xx не совпал со схемой, либо тело запроса не прошло
  ограничения контракта (тогда запрос не отправляется).

| Что                                                       | Повторы                                                      |
| --------------------------------------------------------- | ------------------------------------------------------------ |
| Чтение                                                    | до 2, если ответа не было или статус 408, 429, 502, 503, 504 |
| `seen`, `read`, «прочитать все», `dismiss`                | 1 — по контракту они идемпотентны                            |
| Публикация, исправление, отправка, повтор/отмена доставки | никогда                                                      |

Пауза — из `Retry-After`, если сервис его прислал, иначе 1 с, 2 с, 4 с…
(не больше 30 с).

## Ограничения, которые идут от API

- **В списке нет темы и текста.** `GET /inbox` отдаёт строки без `subject`.
  Кит догружает тему каждой видимой строки по id и хранит в кэше
  (`subjects='none'` — отключить).
- **Нет push-канала.** Счётчик опрашивается раз в 60 с и при возврате на
  вкладку; объявления — раз в 5 минут.
- **«Увидено» и «закрыть» — по одному.** Пакетных команд нет.
- **Нет истории объявлений и списка шаблонов** — см. выше и ниже.

## Администрирование

Три экрана для модераторов. Каждый — один компонент; по страницам и
вкладкам их раскладывает приложение.

| Компонент               | Что это                                                                                                                                                                                                                                  |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NotificationComposer`  | «Рассылка» в одну колонку: кому, куда (плитки каналов), сообщение, параметры; класс и приоритет — в «Дополнительно». Внизу закреплённая панель: число доставок, «Предпросмотр», «Отправить»                                              |
| `DeliveryLog`           | «История доставок»: фильтры, страницы, по строке — ход доставки, текст, повтор и отмена                                                                                                                                                  |
| `AnnouncementPublisher` | «Объявления»: сообщение; кому и как показать (аудитория, категория и подсвеченный по ней вид показа); срок. Внизу — «Предпросмотр» и «Опубликовать» с подтверждением в окне; после публикации — итог, ход почтовой рассылки, исправление |

### Откуда берётся текст сообщения

По контракту у отправки и у объявления **нет поля с текстом**: только ключ
шаблона сервиса и его переменные. Списка шаблонов API не отдаёт, поэтому
кит не показывает никакого каталога. Есть два режима:

1. **«Свой текст»** — тема и текст в редакторе (заголовок, жирный, курсив,
   подчёркнутый, зачёркнутый, списки, цитата, ссылки; вкладка «HTML» для
   разметки). Уходит через шаблон свободного сообщения: переменные
   `subject`, `bodyHtml`, `bodyText` (текстовую версию кит собирает сам).
   Такой шаблон должен быть в сервисе — файлы в `service-templates/`
   репозитория кита, кладутся в папку шаблонов сервиса без релиза. Режим
   включается настройкой `admin.freeformTemplateKey = 'custom-message'`.
   HTML перед отправкой очищается: остаются только перечисленные теги и
   ссылки `http`/`https`/`mailto`.
2. **«Шаблон сервиса»** — ключ любого шаблона, который есть в сервисе, и его
   переменные парами «имя — значение». Без `freeformTemplateKey` доступен
   только этот режим.

### Предпросмотр

Кнопка «Предпросмотр» внизу формы. Сообщение рендерит сам сервис
(`POST /notifications/preview` — тот же рендерер и та же строгость, что при
отправке), а кит проигрывает результат, ничего не отправляя:

- **Рассылка**, меню из выбранных каналов (с одним каналом — без меню):
  - «В кабинете» — на этой же странице всплывает карточка «Новое
    уведомление» (с меткой «Предпросмотр»), в колокольчике +1 и строка
    сверху списка, над формой — жёлтая полоса «Ничего не отправлено» с
    «Выйти из предпросмотра»;
  - «Письмо» — окно: тема, от кого, кому, письмо на сером фоне;
    переключатель HTML / текстовая версия;
  - «Сообщение в чат» — окно в виде переписки: заголовок — тема, текст —
    то, что сервис отправит в чат.

  В окне есть вкладки по выбранным каналам. Вебхук не показывается:
  картинки у него нет.

- **Объявление** — появляется там и так, где и как его увидят: в стопке,
  окном или полосой — по классу категории из `admin.categories`
  (`categoryClass`; если класс неизвестен — в углу, с подсказкой), с
  меткой «Предпросмотр»; над формой — полоса «Так объявление увидят …
  Ничего не опубликовано».

Перед предпросмотром проверяются только поля сообщения; ошибки сервиса
(нет шаблона для канала, не хватает переменной) показываются с его текстом,
кодом ответа и адресом запроса.

### Настройки — проп `admin` провайдера

Сервис не публикует ни каталог категорий, ни роли для аудитории, ни
справочник сотрудников: это конфигурация конкретного развёртывания. Кит
ничего из этого не придумывает; если приложение не передало список, поле
остаётся обычным вводом.

```tsx
const admin: AdminOptions = {
  freeformTemplateKey: 'custom-message',
  categories: [
    /* только реально настроенные в сервисе */
  ],
  roles: [
    /* роли, которые сервис разрешает для объявлений */
  ],
  searchRecipients: (query, signal) => searchEmployees(query, signal),
  permissions: { send: isModerator, announce: isModerator /* … */ },
};
```

| Поле                  | Что это                                                                                                              |
| --------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `freeformTemplateKey` | Ключ шаблона свободного сообщения в сервисе. Без него нет режима «Свой текст»                                        |
| `categories`          | `{ code, label, categoryClass?, announcement? }` — подсказки в поле категории; `announcement: true` — для объявлений |
| `roles`               | `{ code, label }` — роли для аудитории объявления. Пусто — роль вводится текстом                                     |
| `searchRecipients`    | Поиск людей для поля «Получатели» → `RecipientDraft[]`. Без него вводят ID пользователя или e-mail                   |
| `maxVisibilityDays`   | Предел срока показа объявления, по умолчанию 90 (`announcements.max-visibility-window` сервиса)                      |
| `permissions`         | `send`, `preview`, `deliveries`, `retryDeliveries`, `announce`. По умолчанию всё разрешено, а решает сервис (403)    |

Роли сервиса (`@PreAuthorize` контроллеров на закреплённом коммите):

| Флаг              | Роли сервиса                                 | Что открывает                                      |
| ----------------- | -------------------------------------------- | -------------------------------------------------- |
| `send`            | `NOTIFICATION_SENDER`, `NOTIFICATION_ADMIN`  | `NotificationComposer`                             |
| `preview`         | `NOTIFICATION_AUTHOR`, `NOTIFICATION_ADMIN`  | Предпросмотр в формах                              |
| `deliveries`      | `NOTIFICATION_SUPPORT`, `NOTIFICATION_ADMIN` | `DeliveryLog`, подробности строки, отмена доставки |
| `retryDeliveries` | `NOTIFICATION_ADMIN`                         | «Отправить повторно» у недоставленной              |
| `announce`        | `NOTIFICATION_ANNOUNCER`                     | `AnnouncementPublisher`, исправление, почта        |

### Повторы и защита от двойного действия

- Отправка не повторяется автоматически. Каждая идёт с `Idempotency-Key`;
  повторное нажатие с теми же данными (например, после обрыва сети) уходит
  с тем же ключом, и сервис не отправит дважды.
- Публикация не идемпотентна: перед ней форма просит подтверждения.
- Ход почтовой рассылки опрашивается с паузой из `Retry-After` (1–30 с) до
  завершения; её можно остановить (уже созданные письма не отзываются).
- Текст доставки читается только по кнопке: каждое чтение пишется в аудит.
  Ответ 410 — «Текст удалён по сроку хранения».

### Ограничения, которые идут от API

- **Нет списка опубликованных объявлений** — после публикации показан итог
  этой публикации; вернуться к ней позже из интерфейса нельзя.
- **Нет повторяющихся рассылок** — только «сразу» или к моменту времени.
- **Получатели — явный список**, не больше 500 в запросе.
- **Снять объявление нельзя** — только исправить текст; аудитория и срок
  показа не меняются.
- **Чат и вебхук** в сервисе по умолчанию выключены.
