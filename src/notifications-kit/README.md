# notifications-kit

Клиент сервиса уведомлений и интерфейс поверх него: колокольчик, лента,
просмотр уведомления, объявления (баннеры), а для модераторов — рассылки,
история доставок и публикация объявлений. Версия 0.2.

Папка самодостаточна: её можно перенести в проект целиком. Внутри нет
импортов из приложения, HTTP-клиента и UI-библиотек.

Зависимости, которые должны быть в проекте:
`react` 18, `react-dom` 18, `@tanstack/react-query` 5, `zod` 4.
Сборщик должен понимать CSS-модули (`*.module.css`).

## Устройство

```
core/      контракт, клиент, ошибки, повторы, OData — без React
  generated/   схемы и таблица операций, собраны из OpenAPI; руками не править
react/     провайдер, хуки, компоненты, стили
```

## Подключение

### 1. Транспорт

Кит не делает запросы сам. Ему передают функцию, которая выполняет один
запрос и **возвращает ответ при любом статусе**: по телу ошибки кит читает
стабильный `code`. Перехватчик, который превращает 4xx/5xx в исключение или
переписывает тело, для этой функции не подходит — нужен отдельный экземпляр
клиента.

```ts
import axios from 'axios';
import type { NotificationsTransport } from '@/lib/notifications-kit';

const http = axios.create({
  baseURL: '/api/notifications', // префикс, под которым сервис стоит за шлюзом
  validateStatus: () => true, // статус разбирает кит
});

export const transport: NotificationsTransport = async request => {
  const response = await http.request({
    method: request.method,
    url: request.path, // '/api/v1/inbox/…' — путь из контракта
    params: new URLSearchParams(request.query.map(([k, v]) => [k, v])),
    headers: request.headers,
    data: request.body,
    signal: request.signal,
  });
  return {
    status: response.status,
    headers: response.headers as Record<string, string>,
    data: response.data,
  };
};
```

Если запрос не дошёл (сеть, таймаут, отмена), функция должна выбросить
исключение — как это и делает axios.

### 2. Провайдер

```tsx
import {
  AnnouncementsHost,
  NotificationsProvider,
  createNotificationsApi,
  presentationByCategory,
} from '@/lib/notifications-kit';

const api = createNotificationsApi({
  transport,
  acceptLanguage: () => i18n.language,
});

const resolvePresentation = presentationByCategory(
  { 'platform-incident': 'modal', 'platform-release': 'corner' },
  'corner'
);

<QueryClientProvider client={queryClient}>
  <NotificationsProvider
    api={api}
    locale='ru'
    enabled={isSignedIn}
    resolvePresentation={resolvePresentation}
  >
    <App />
    <AnnouncementsHost />
  </NotificationsProvider>
</QueryClientProvider>;
```

`api` и функции, передаваемые в провайдер, создаются один раз (вне
компонента или через `useMemo`/`useCallback`).

### 3. Компоненты

| Компонент                                     | Что это                                                              | Основные пропсы                                       |
| --------------------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------- |
| `NotificationBell`                            | Кнопка в шапке: счётчик и выпадающий список                          | `anchorRef`, `onOpenItem`, `onOpenAll`, `limit`       |
| `InboxPanel`                                  | Лента целиком: фильтр, «Прочитать все», строки, «Показать ещё»       | `onOpenItem`, `pageSize`, `showBar`, `rowActions`     |
| `InboxTabs`, `MarkAllReadButton`, `InboxList` | Те же части по отдельности — чтобы разложить по зонам своей страницы | —                                                     |
| `InboxItemView`                               | Одно уведомление с темой и текстом (отдельная страница)              | `id`, `autoMarkRead`, `onDismissed`, `showSubject`    |
| `AnnouncementsHost`                           | Объявления поверх страницы; монтируется один раз                     | `toastDurationMs`, `toastOnTimeout`, `cornerPosition` |

Навигации в ките нет: куда вести по клику, решает приложение через
`onOpenItem` и `onOpenAll`.

**Строка ленты раскрывается на месте.** Клик показывает текст и отмечает
уведомление прочитанным (`POST …/read`); внутри — «Скрыть» и, если передан
`onOpenItem`, «Открыть отдельно». Отдельная страница уведомления нужна
только для прямых ссылок; заголовок для её шапки даёт
`useInboxItemTitle(id)`.

**Колокольчик и шапка.** Список колокольчика выводится в `<body>` (его не
обрежет `overflow` шапки) и по умолчанию висит под кнопкой. Чтобы его
правый край совпал с краем шапки, передайте ref шапки:
`<NotificationBell anchorRef={headerRef} />`; отступ от края —
`anchorInset` (по умолчанию 16 px).

Строка ленты никогда не показывает сырой код категории: до прихода темы —
подпись из `describeItem`, без неё — «Уведомление».

Хуки для своих компонентов: `useUnreadCount`, `useUnreadBadge`,
`useInboxList`, `useInboxItem`, `useInboxCommands`, `useAnnouncements`,
`useOutstandingAnnouncementCount`, `useDismissAnnouncement`.
`useUnreadBadge()` возвращает `number | undefined` — в форме, удобной для
бейджа пункта меню.

## Объявления: три вида показа

Сервис сообщает, **что** это за объявление (`category`, `categoryClass`), и
не имеет поля «как показывать». Вид выбирает приложение функцией
`resolvePresentation`; готовый вариант — `presentationByCategory`.

| Вид      | Как выглядит                                                                                 | Что делает закрытие                              |
| -------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `modal`  | Диалог поверх страницы, пока не нажата «Понятно». Несколько — по одному, от старого к новому | «Понятно» → `dismiss` в сервисе                  |
| `corner` | Небольшая карточка в углу, до трёх одновременно                                              | «×» → `dismiss` в сервисе                        |
| `toast`  | Полоса сверху по центру на несколько секунд                                                  | «×» → `dismiss`. По истечении времени — см. ниже |
| `none`   | Поверх страницы не показывается                                                              | —                                                |

У `toast` конец времени по умолчанию **не** считается прочтением: полоса
скрывается до закрытия вкладки браузера, сервис продолжает считать
объявление непросмотренным, и в новой сессии оно появится снова — пока не
закрыто крестиком или не истёк срок показа. Чтобы истечение времени
закрывало объявление насовсем: `<AnnouncementsHost toastOnTimeout='dismiss' />`.

Карточки `corner` стоят в правом верхнем углу и могут закрывать кнопки
страницы под собой. Положение меняется пропом `cornerPosition='bottom-end'`
или переменными `--nk-overlay-top`, `--nk-overlay-inline`,
`--nk-overlay-bottom`.

HTML-тело (`bodyHtml`) кит сам в страницу не вставляет. Без пропа
`renderHtml` показывается текстовое тело. Чтобы показывать HTML, передайте в
провайдер свой рендерер с очисткой.

## Тексты

Встроены словари `ru` и `en`; выбор — по `locale`. Отдельные строки
заменяются пропом `messages`, весь механизм — пропом `translate`. Ключи —
в `react/messages.ts`.

Подписи строк ленты по `templateKey`/`category` даёт приложение через
`describeItem` (см. «Ограничения»).

## Ошибки и повторы

Любая ошибка кита — `NotificationsError` с полем `kind`:

- `problem` — сервис ответил не 2xx; доступны `status`, `code`, `title`,
  `detail`, `traceId`, `retryAfterMs`. Ветвиться нужно по `code`;
- `network` — ответа не было;
- `contract` — ответ 2xx не совпал со схемой, либо тело запроса не прошло
  ограничения контракта (тогда запрос не отправляется).

Что повторяется автоматически:

| Что                                        | Повторы                                                      |
| ------------------------------------------ | ------------------------------------------------------------ |
| Чтение                                     | до 2, если ответа не было или статус 408, 429, 502, 503, 504 |
| `seen`, `read`, «прочитать все», `dismiss` | 1 — по контракту они идемпотентны                            |
| Публикация, исправление, отправка          | никогда                                                      |

Пауза — из `Retry-After`, если сервис его прислал, иначе 1 с, 2 с, 4 с…
(не больше 30 с). Отправка уведомления (`api.requests.submit`) безопасна к
повтору только с `idempotencyKey`.

## Ограничения, которые идут от API

- **В списке нет темы и текста.** `GET /inbox` отдаёт строки без `subject`.
  По умолчанию кит догружает тему каждой видимой строки отдельным запросом
  и хранит её в кэше. Отключается: `subjects='none'` — тогда строка
  подписана тем, что вернул `describeItem`.
- **Нет push-канала.** Счётчик опрашивается: раз в 60 с и при возврате на
  вкладку (`polling.unreadCountMs`). Объявления — раз в 5 минут.
- **«Увидено» отправляется по одному.** Пакетной команды нет, поэтому на
  каждую впервые показанную строку уходит свой `POST …/seen`. Отключается:
  `markSeen={false}`.
- **Нет настроек подписок и списка шаблонов** — в контракте таких операций
  нет, в ките их тоже нет.

## Администрирование (0.2)

Три экрана для модераторов. Каждый — один компонент, разложить их по
страницам и вкладкам решает приложение.

| Компонент               | Что это                                                                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `NotificationComposer`  | «Рассылка»: шаблон и его данные, получатели, каналы, категория, класс, приоритет, «сразу / запланировать», предпросмотр, итог с доставками      |
| `DeliveryLog`           | «История доставок»: фильтры (канал, шаблон, номер запроса, период, статусы), страницы, по строке — ход доставки, текст, повтор и отмена         |
| `AnnouncementPublisher` | «Объявления»: категория, аудитория (все / роль), шаблон, срок показа, предпросмотр, подтверждение; ниже — опубликованные, ход почтовой рассылки |

Части тоже экспортируются: `TemplatePreview`, `RecipientField`,
`DeliveryTable`, `PublishedAnnouncements`, `EmailRunProgress` и хуки
`useSendNotification`, `useTemplatePreview`, `useDeliverySearch`,
`useDeliveryCommands`, `usePublishAnnouncement`, `useCorrectAnnouncement`,
`useEmailRun`, `useCancelEmailRun`.

### Настройки — проп `admin` провайдера

Сервис не публикует каталог категорий, список ролей для аудитории и
справочник сотрудников: в его репозитории это конфигурация
(`categories: {}`, `targetable-roles: []`). Их даёт приложение:

```tsx
const admin: AdminOptions = {
  categories: [
    { code: 'preorder', label: 'Предзаказы', categoryClass: 'TRANSACTIONAL' },
    { code: 'platform-release', label: 'Выпуск', announcement: true },
    { code: 'platform-incident', label: 'Работы и сбои', announcement: true },
  ],
  roles: [{ code: 'MODERATOR', label: 'Модераторы' }],
  templateLabels: { welcome: 'Приветствие' },
  variableLabels: { productName: 'Продукт' },
  searchRecipients: (query, signal) => searchEmployees(query, signal),
  permissions: { send: isModerator, announce: isModerator /* … */ },
};

<NotificationsProvider api={api} admin={admin}>
  …
</NotificationsProvider>;
```

| Поле                | Что это                                                                                                                                 |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `categories`        | Подсказки категории при отправке; `categoryClass` подставляется в форму. С `announcement: true` — список категорий объявлений           |
| `roles`             | Роли для аудитории объявления (`audienceValue`). Пусто — роль вводится текстом                                                          |
| `templateLabels`    | Человеческие названия шаблонов                                                                                                          |
| `variableLabels`    | Названия полей шаблона                                                                                                                  |
| `searchRecipients`  | Поиск людей для поля «Получатели», возвращает `RecipientDraft[]` (`userId` или `address`). Без него вводится ID пользователя или e-mail |
| `maxVisibilityDays` | Предел срока показа объявления (`announcements.max-visibility-window` сервиса), по умолчанию 90                                         |
| `permissions`       | `send`, `preview`, `deliveries`, `retryDeliveries`, `announce`. По умолчанию всё разрешено, а решает сервис ответом 403                 |

Роли сервиса (`@PreAuthorize` контроллеров на том же коммите):

| Флаг              | Роли сервиса                                 | Что открывает                                      |
| ----------------- | -------------------------------------------- | -------------------------------------------------- |
| `send`            | `NOTIFICATION_SENDER`, `NOTIFICATION_ADMIN`  | `NotificationComposer`                             |
| `preview`         | `NOTIFICATION_AUTHOR`, `NOTIFICATION_ADMIN`  | Предпросмотр в формах                              |
| `deliveries`      | `NOTIFICATION_SUPPORT`, `NOTIFICATION_ADMIN` | `DeliveryLog`, подробности строки, отмена доставки |
| `retryDeliveries` | `NOTIFICATION_ADMIN`                         | «Отправить повторно» у недоставленной              |
| `announce`        | `NOTIFICATION_ANNOUNCER`                     | `AnnouncementPublisher`, исправление, почта        |

Флаги только прячут то, что сервис всё равно отклонит; при 403 компонент
показывает «Недостаточно прав».

### Шаблоны

Своего текста сервис не принимает: отправка и объявление — это ключ
шаблона и значения его переменных. Список шаблонов кит знает из файлов
сервиса (`core/generated/templates.ts`, собран из шаблонов того же
коммита, что и контракт): каналы, языки, обязательные и необязательные
переменные, годится ли шаблон для объявления (без обращения к получателю)
и не дайджест ли он. Шаблон, которого ещё нет в списке, можно указать
вручную — «Другой ключ шаблона…».

Предпросмотр рендерит сервис (`POST /notifications/preview`) с той же
строгостью, что при отправке: если не хватает переменной, это видно до
отправки. HTML показывается в изолированном `iframe` без скриптов.

### Повторы и защита от двойного действия

- Отправка не повторяется автоматически. Каждая отправка идёт с
  `Idempotency-Key`; если человек нажмёт «Отправить» ещё раз с теми же
  данными (например, после обрыва сети), ключ тот же и сервис не отправит
  дважды. Изменили данные — ключ новый.
- Публикация объявления не идемпотентна по контракту: перед ней форма
  просит подтверждения, и она никогда не повторяется сама.
- Ход почтовой рассылки опрашивается с паузой из `Retry-After` (от 1 до
  30 с) и останавливается, когда операция завершена.
- Текст доставки читается только по кнопке: сервис пишет каждое чтение в
  журнал аудита. Ответ 410 — «Текст удалён по сроку хранения».

### Ограничения, которые идут от API

- **Нет списка опубликованных объявлений.** Под формой показаны только
  опубликованные из этой вкладки браузера (хранятся в `sessionStorage`).
- **Нет повторяющихся рассылок.** Только «сразу» или «в момент времени»
  (`scheduledAt`).
- **Получатели — явный список**, не больше 500 в запросе; рассылки «на
  роль» у уведомлений нет (у объявлений — есть).
- **Снять объявление нельзя** — только исправить текст; аудитория и срок
  показа после публикации не меняются.
- **Чат и вебхук** в конфигурации сервиса по умолчанию выключены: если у
  шаблона есть текст для них, кит их предложит, а сервис может отклонить.

### Дополнительные переменные темы

`--nk-color-danger`, `--nk-color-danger-soft`, `--nk-color-success`,
`--nk-color-warning-soft`, `--nk-color-warning-border`,
`--nk-color-surface-sunken`, `--nk-color-surface-input` — ошибки, успех,
предупреждения, фон предпросмотра и шапки таблицы, фон полей ввода.

## Что ещё есть в `core`

`createNotificationsApi` покрывает все операции контракта, в том числе
пакетную отправку и стоп-лист. Интерфейса для них в 0.2 нет.
