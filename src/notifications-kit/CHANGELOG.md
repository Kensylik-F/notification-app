# Изменения

## 0.6.7

- Отменено 0.6.6: в окне правки снова только текст (или параметры
  шаблона) через `POST /announcements/{id}/corrections`; полей «С» / «По»
  и «Снять с показа» нет, даты в исправлении не отправляются. Изменение
  срока и снятие с показа появятся, когда в notification-service будут
  свои запросы для этого.

## 0.6.5

- Исправление объявления, которое публикующий у себя уже закрыл: в
  «Опубликованных» и в «Закрытые ранее» теперь виден исправленный текст
  (раньше оставался текст на момент закрытия).

## 0.6.4

- **Убрано всё, чего нет в notification-service:** блок «Срок показа»,
  кнопка «Снять с показа», запрос `POST /announcements/{id}/window`, флаг
  `features.announcementWindow`, `api.announcements.changeWindow`. Кит
  снова делает только то, что есть в сервисе: правка текста через
  `corrections`.
- Категории объявлений — как в 0.6.3: `custom-transitions` /
  `custom-notice` / `custom-marketing` по виду.

## 0.6.3

- **Категория объявления зашита в кит.** Клик по виду отправляет в
  `category`: «Окном по центру» → `custom-transitions`, «Полосой сверху» →
  `custom-notice`, «Справа сверху» → `custom-marketing`. Коды больше не
  берутся из `admin.categories` (`announcement: true` ни на что не влияет),
  так что старые коды из конфига приложения (`platform-release` и др.) в
  запрос не попадут. Переопределить — `admin.announcementCategories`.
  Константа — `DEFAULT_ANNOUNCEMENT_CATEGORIES`.
- **Срок показа и «Снять с показа» выключены по умолчанию**
  (`features.announcementWindow: false`): в notification-service нет
  эндпоинта `POST /announcements/{id}/window`, на стенде он отвечал 404.
  Правка текста (`corrections`) работает как раньше. Включить — когда
  эндпоинт появится (`docs/spec-announcement-window.md`).
- Поле ручного ввода категории в форме объявления убрано.

## 0.6.2

- **Срок показа и снятие с показа.** В окне правки объявления (в
  «Опубликованных», в «Уведомления → Объявления» и после публикации) —
  блок «Срок показа» (С / По) и кнопка «Снять с показа». «Снять с показа»
  после подтверждения ставит окончание на конец вчерашнего дня (23:59) —
  объявление больше никому не показывается. Дата «По» в прошлом,
  сохранённая вручную, делает то же самое (тоже с подтверждением).
- Запрос: `POST /announcements/{id}/window`, тело
  `{ visibleFrom?, visibleUntil }`, ответ `AnnouncementAdmin`. **В
  notification-service этого эндпоинта пока нет** — нужна доработка сервиса
  (`docs/spec-announcement-window.md`). Пока его нет, кит показывает
  «Сервис уведомлений пока не умеет менять срок показа». Флаг
  `features.announcementWindow` (по умолчанию включён) прячет блок и кнопку.
- Новое: `api.announcements.changeWindow`, хук
  `useChangeAnnouncementWindow`. `onDone` редактора и `onSaved` окна правки
  получают `{ removed }`.
- Демо: коды категорий объявлений — `custom-transitions` (TRANSACTIONAL),
  `custom-notice` (PLATFORM), `custom-marketing` (MARKETING); мок
  поддерживает `/window`.

## 0.6.1

- Окно правки: кнопки «Сохранить / Предпросмотр / Отмена» всегда видны,
  когда содержимое окна прокручивается; вкладки в нём называются «Свой
  текст» / «Шаблон сервиса» (не «Создать…»).
- Окно правки подставляет текст и у объявлений без HTML (только
  `bodyText`): раньше поле «Текст» открывалось пустым.
- Демо: исправление работает и для объявлений, которые были в моке с
  начала (раньше — только для опубликованных в демо).

## 0.6.0

- **Изменение опубликованных объявлений.** Новый компонент
  `PublishedAnnouncements`: список опубликованных с «Изменить» у каждого;
  правка — в окне, через `POST /announcements/{id}/corrections` (текст или
  параметры шаблона; аудитория, вид и срок не меняются). В
  `NotificationCenter` у открытого объявления — «Изменить» для тех, у кого
  есть `features.publishing` и `permissions.announce`; новый проп
  `onEditAnnouncement`. Отдельно экспортируются `AnnouncementEditDialog` и
  `AnnouncementEditor`.
- Кит запоминает каждый опубликованный запрос в браузере (по
  `storageScope`): сервис не хранит параметры шаблона и не отдаёт список
  опубликованного, а для правки нужны все параметры.
- **Форма объявления по-новому.** Сверху — вкладки «Создать своё
  объявление» / «Создать из шаблона» (в объявлениях всегда, флаг
  `serviceTemplates` теперь только для рассылок). Первая секция — «Кому и
  как показать»: плитки вида и аудитория. **Поля «Категория» больше нет** —
  категорию задаёт клик по виду; выбранная показана строкой под плитками.
  Поле для кода остаётся, только если `admin.categories` пуст.
- Шаблон: «Название шаблона» и «Параметры шаблона» (ключ — значение,
  «Добавить параметр»).
- **Язык предпросмотра** RU / EN в секции «Сообщение» и в окне правки.
  Новая настройка `admin.locales` (по умолчанию `['ru', 'en']`). Сервис
  публикует на всех языках сразу.
- Окно правки показывает предпросмотр внутри себя.
- Демо: страница «Объявления» с вкладками «Новое объявление» /
  «Опубликованные»; мок исправления, как сервис, рендерит шаблон самого
  объявления.
- Файлов в папке кита — 58.

## 0.5.7

- **Выпадающие списки в формах кликаются и непрозрачны.** Список
  («Категория», «Роль», каналы, фильтры журнала) рендерится в `<body>` с
  фиксированной позицией. Раньше он жил внутри поля: следующая секция формы
  или карточка хоста со своим контекстом наложения рисовалась поверх него,
  просвечивала сквозь него и забирала клики. У нижнего края окна список
  открывается вверх. Фон — `--nk-color-surface-raised` поверх
  `--nk-color-popover` (по умолчанию `Canvas`), полупрозрачная тема не
  просвечивает.
- **Нижняя панель формы — в отдельной секции.** Новый проп
  `actionsContainer` у `AnnouncementPublisher` и `NotificationComposer`:
  панель рендерится в переданный элемент (зону футера страницы), под
  прокруткой, а не поверх формы. Без пропа — как раньше, прилипает к низу.
  Фон панели непрозрачный в обоих случаях: `--nk-color-surface-bar` поверх
  `--nk-color-bar-base` (по умолчанию `Canvas`); `backdrop-filter` убран.
- В папке кита новый файл `react/admin/ActionBar.tsx` (всего файлов — 54).
- Демо: `?dock=1` — панель объявления в футере под прокруткой.

## 0.5.6

- **Пути без `/api` и `/v1`.** Кит отправляет `/inbox`, `/announcements`,
  `/notifications/…` — без префикса шлюза и версии. Имена операций тоже
  без них: `'GET /inbox'` вместо `'GET /api/v1/inbox'`. Генератор контракта
  убирает префикс при сборке `OPERATIONS`.
- `requestPath` снимает `/api`, `/v1` и `/api/v1`, если путь пришёл с ними.
  `CONTRACT_PREFIX` удалён.
- Кто вызывал `client.call('GET /api/v1/…')` напрямую — поменять ключ на
  `'GET /…'`. Моки, которые сверяли путь `/v1/…`, — сверять `/…`.

## 0.5.5

- **Ссылки внутрь кабинета.** В редакторе можно указать путь
  (`/preorders/new?source=4821`): он сохраняется полным адресом на домене
  кабинета (работает и в письме). В кабинете такая ссылка с новым пропом
  провайдера `navigate` (роутер приложения) открывается на месте, окно с
  ней закрывается; важное окно при этом считается прочитанным.
- **Таблицы** сохраняются в редакторе (раньше превращались в слитный
  текст); в текстовой версии — строками через «|». Вложенные списки в
  текстовой версии — с отступами.
- **Сломанная разметка**: жирный, оставшийся открытым через несколько
  абзацев, больше не даёт `<p>` внутри `<p>`.
- **HTML от сервиса чистится перед показом** (`cleanForDisplay`): без
  `<style>` (мог скрыть весь текст), форм, фреймов, скриптов, `on…` и
  `javascript:`.
- Демо: `?samples=html` — набор сложных и сломанных примеров
  (`demo/html-samples.ts`), `&clean=1` — они же после редактора;
  `scripts/html-samples.mjs` снимает их.

## 0.5.0

### Объявления: вид по классу и очередь

- **Вид показа — по `categoryClass`** (раньше по умолчанию всё шло в
  угол): `TRANSACTIONAL` — окно по центру, `PLATFORM` — полоса сверху,
  `MARKETING` и без класса — стопка справа. Новое: `presentationByClass`,
  `CLASS_PRESENTATION`. `presentationByCategory(map, otherwise)` — для
  неперечисленных категорий теперь по классу (второй аргумент может быть
  видом или функцией).
- **Очередь** вместо показа всего сразу: через 1,5 с после загрузки —
  окна по одному («1 из N»), затем полосы по одной, затем стопка. Между
  закрытием и следующим — 0,8 с. Новое не перебивает показанное.
  Пропсы `AnnouncementsHost`: `firstDelayMs`, `gapMs`, `stripDurationMs`
  (по умолчанию 0 — полоса висит, пока не закроют). Стопка без
  ограничения (`maxCorner` по умолчанию — без предела).
- Убраны пропсы `toastOnTimeout`, `maxToasts` и функция
  `planAnnouncements` (теперь `queueAnnouncements`).

### Новый вид окна и полосы

- Окно: страница позади размыта (`Dialog backdrop='blur'`), цветная
  полоса сверху, значок с пульсацией, «ВАЖНОЕ» для `TRANSACTIONAL`,
  заголовок 22 px, срок показа, «Понятно».
- Полоса: шире (до 680 px), значок на цветной плашке, заголовок и две
  строки текста, «1 из N». За ней — размытие верха страницы до низа
  полосы. Уход — вверх вместе с размытием.
- `--nk-corner-top` — отступ стопки сверху отдельно от полос (например,
  высота шапки, чтобы не закрывать колокольчик).
- Новые переменные: `--nk-color-scrim-blur`, `--nk-color-band`,
  `--nk-color-strip-border`, `--nk-color-danger-border`.

### Колокольчик и страница

- Колокольчик показывает объявления: активные (важные сверху),
  «Просмотренные» (последние закрытые, `seenLimit`), затем входящие.
  Счётчик — активные объявления плюс непрочитанные. Новый проп
  `onOpenAnnouncement`.
- Красная точка и «Важное» у `TRANSACTIONAL` в списках и в тексте.
- `NotificationCenter` без вкладок, если включена одна часть.

### Части кита — `features`

- Проп провайдера `features`: `bell`, `announcements`, `banners`, `inbox`,
  `mailings`, `publishing` (по умолчанию всё включено). Выключенное не
  рисуется и не делает запросов.

### Ошибки

- Ошибка фонового чтения (список объявлений, счётчики, лента) — в том
  числе ответ, не совпавший с контрактом, — уходит в `onError` один раз.
  Раньше такой ответ просто оставлял экран пустым.

## 0.4.0

Новый вид всего кита — по макету «Уведомления OneCheck — макет 0.4».

### Объявления поверх страницы

- (в 0.4.1 заменено) Всплывающее жило в рабочей области страницы.
- **Стопка, как на телефоне**: спереди новая карточка, сверху выглядывают
  ещё две; «ещё N» — внутри карточки. Клик раскрывает стопку списком с

  Карточки переезжают между видами (FLIP), закрытая уезжает вправо,
  остальные смыкаются; «Закрыть все» — каскадом.
- **Кнопка закрытия** — круг 28 px с заливкой и крестиком 12 px (было «×»
  без фона). Наведение, нажатие и фокус видны.
- Полный текст — по клику на карточку или «Подробнее»: окно с «Больше не
  показывать» (или `onOpenAnnouncement` приложения).
- Окно `modal` и полоса `toast` в том же стиле, с анимацией появления и
  ухода.
- **Новое уведомление**: когда счётчик растёт, в углу появляется карточка
  «Новое уведомление» на 8 секунд (наведение — пауза), «Открыть» →
  `onOpenItem`. Отключается `inboxToasts={false}`.

### Страница уведомлений — `NotificationCenter` (новое)

- Одна строка вкладок вместо двух уровней: «Входящие N» · «Объявления N»,
  подчёркивание переезжает. «Только непрочитанные» — переключатель справа.
- Слева список (точка, тема, время, первая строка текста), справа —
  выбранное целиком: тема, дата, «Важное», категория, HTML, «Закрыть»,
  «Открыть на отдельной странице». Строки больше не раскрываются на месте.
- «Закрыть» — строка уезжает, открывается следующая.
- «Объявления»: «Активные» и «Закрытые ранее» одним списком, справа — текст
  с «Показывается до …» / «Показывалось до …».
- Уже 720 px — список и текст по очереди, с «К списку».
- Вкладка, выбранное и фильтр — управляемые (для адресной строки).

Удалены `InboxPanel`, `InboxTabs`, `AnnouncementFeed` — их заменяет
`NotificationCenter`. `InboxActions` — «Прочитать все» и «Закрыть все» для
шапки страницы. У `InboxList` вместо раскрытия строк — `selectedId` и
`onSelect`. `InboxItemView` получил вид правой панели и `onOpenSeparately`.

### Колокольчик

- Строки как в списке страницы; клик ведёт в `onOpenItem`.
- «Прочитать все» — ссылкой в шапке списка; счётчик «подпрыгивает», когда

### Рассылка и объявление

- Одна колонка без боковой панели предпросмотра. Секции без номеров:
  «Кому», «Куда» (плитки каналов с иконками и отметкой), «Сообщение»

  (категория и «Когда» рядом; «Дополнительно: класс · приоритет» —

- **Нижняя панель закреплена**: «2 получателя × 3 канала = 6 доставок»
  (с правильными окончаниями), «Предпросмотр», «Отправить».
- **Предпросмотр по кнопке** вместо постоянной панели:
  - «В кабинете» — карточка нового уведомления на этой странице, +1 и
    строка в колокольчике, полоса «Ничего не отправлено» над формой;
  - «Письмо» — окно с письмом (тема, от, кому, HTML / текст);
  - «Сообщение в чат» — окно в виде переписки.
  - Объявление показывается там и так, как его увидят (стопка, окно,
    полоса — по категории).
- Редактор: панель в одну строку — «Абзац ▾» (абзац, заголовок, цитата),
  B I U S, списки, ссылка, очистка; справа `</> HTML`.
- Объявление: вид показа подсвечивается сам по введённой категории;
  подтверждение публикации — в окне.
- Неудачная проверка прокручивает к первому отмеченному полю.
- Каналы «В приложении» → «В кабинете».

### Ошибки

- Ответ без описания (шлюз, заглушка, несуществующий адрес) больше не
  превращается в «Не удалось выполнить действие»: показываются код ответа и
  адрес запроса; 404 — «Сервис не знает этот адрес».

### Шаблон свободного сообщения

- `service-templates/custom-message/chat/` — для канала чата. Сервис
  отправляет в чат `body.html.ftl` как тело и `subject.ftl` как заголовок
  (`InternalChatChannel`), поэтому в чат уходит `${bodyText}`.

### Прочее

- `Tabs`, `Switch`, `Button`, `CloseButton`, `Dialog`, `Chip`,
  `formatListTime`, `formatCardTime`, `formatDay`, `plural` — в публичном
  API.
- Палитра по умолчанию — из макета; новые переменные `--nk-*` — в README.
- Всё движение выключается при `prefers-reduced-motion: reduce`.

## 0.3.1

Исправления после проверки 0.3.0:

- Редактор больше не меняет поведение Enter во всём документе (раньше
  включал `defaultParagraphSeparator` глобально — это задевало другие
  редактируемые поля приложения).

  показывали её по-разному); неразрывные пробелы редактора заменяются
  обычными; пустые строки не отправляются, а стёртый текст снова считается
  пустым (возвращается подсказка, срабатывает проверка «напишите текст»).
- Вкладка «HTML»: форма и предпросмотр следуют разметке сразу при вводе, а
  не только при уходе из поля.
- Переключение «Свой текст» ↔ «Шаблон сервиса» не стирает уже введённое.
- Подтверждение публикации на роль: «с ролью «Модераторы»» вместо «с ролью
  «Роли: Модераторы»».
- Группы радиокнопок уникальны на странице: две формы рядом больше не
  мешают друг другу.
- Поле категории закрывает подсказки при уходе фокуса (Tab).
- HTML в рамке подстраивает высоту под содержимое при любых изменениях
  (шрифты, картинки, ширина) и перекрашивается при смене темы.
- В таблице доставок вместо ключа шаблона свободного сообщения — «Свой
  текст».
- Текстовая версия письма не дублирует адрес `mailto:` ссылки.
