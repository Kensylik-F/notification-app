# Перенос notifications-kit в приложение

Порядок рассчитан на то, что переносит и подключает другой человек или
агент. Папку библиотеки при этом **не редактируют**: всё, что зависит от
приложения, живёт снаружи, в файлах подключения.

## 1. Перенос

1. Скопировать `src/notifications-kit/` в проект, например в
   `src/lib/notifications-kit/`. Больше ничего из этого репозитория не нужно.
2. Убедиться, что в проекте есть `react` 18, `react-dom` 18,
   `@tanstack/react-query` 5, `zod` 4. Новых зависимостей кит не требует.
3. Запустить тесты проекта: в папке три файла тестов (`core/core.test.ts`,
   `core/admin.test.ts`, `react/react.test.ts`), им нужен только `vitest` в
   окружении `node`.
4. Если форматтер проекта настроен иначе — отформатировать папку им. Это
   единственное допустимое изменение файлов кита.

## 2. Файлы подключения (вне папки кита)

| Файл      | Что в нём                                                                                                                                                       |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| транспорт | Функция `NotificationsTransport` на HTTP-клиенте проекта. Отдельный экземпляр клиента: без перехватчиков, переписывающих ошибки, с `validateStatus: () => true` |
| `api`     | `createNotificationsApi({ transport, acceptLanguage })` — один раз на приложение                                                                                |
| тема      | CSS с объявлением переменных `--nk-*` через токены проекта, для светлой и тёмной темы                                                                           |
| подписи   | `describeItem` (подпись строки по `category`/`templateKey`) и `resolvePresentation` (вид показа объявления по `category`)                                       |
| админка   | `admin` провайдера: категории, роли для аудитории, названия шаблонов и полей, поиск сотрудников, права по ролям пользователя                                    |
| провайдер | `NotificationsProvider` под `QueryClientProvider` проекта, `enabled` — пока пользователь не загружен, `false`                                                   |

Примеры кода для каждого — в README кита.

## 3. Места в интерфейсе

1. **Шапка** — ref на корневой элемент шапки сайта для колокольчика
   (`anchorRef`).
2. **Колокольчик** — `NotificationBell` в шапке, `anchorRef` — ref шапки.
   `onOpenAll` ведёт на страницу уведомлений, `onOpenItem` — на неё же с
   выбранным уведомлением.
3. **Страница уведомлений** — `NotificationCenter`. Вкладку и выбранное
   держать в адресе (`tab`, `selectedId` и их `on…Change`); «Прочитать все»
   и «Закрыть все» — `<InboxActions />` в шапке страницы (или `title` у
   самого компонента).
4. **Страница одного уведомления** (прямые ссылки) — `InboxItemView` с `id`
   из адреса.
5. **Всплывающее** — один `AnnouncementsHost` рядом с корнем приложения,
   `onOpenItem` — тот же переход, что у колокольчика.
6. **Бейдж в меню** — `useUnreadBadge()`.
7. **Модерирование** — «Рассылки» (`NotificationComposer` и `DeliveryLog`
   на вкладках `Tabs` кита) и «Объявления» (`AnnouncementPublisher`).
   Показывать только тем, у кого есть права.

## 4. Проверка

- [ ] Счётчик на колокольчике совпадает с `GET /api/v1/inbox/unread-count`.
- [ ] В запросах ленты параметры называются `$filter`, `$top`, `$skip`;
      параметра `options` нет.
- [ ] Открытие уведомления отправляет `POST …/read` один раз; счётчик
      уменьшается.
- [ ] «Прочитать все» обнуляет счётчик; повторное нажатие недоступно.
- [ ] «Закрыть» убирает строку; уведомление по прямому адресу открывается.
- [ ] Стопка объявлений — поверх всего в правом верхнем углу окна;
      раскрывается и сворачивается.
- [ ] «Предпросмотр» в рассылке: «В кабинете» — карточка и строка в
      колокольчике; «Письмо» и «Сообщение в чат» — окна; ничего не уходит
      в `POST /api/v1/notifications`.
- [ ] Ответ 404 на чужое уведомление показывает «Уведомление не найдено».
- [ ] Объявление каждого вида показывается и закрывается; после закрытия
      не возвращается при перезагрузке.
- [ ] Светлая и тёмная тема; ширина окна 1366 и 1920.
- [ ] При выключенном сервисе страницы приложения работают, в ките —
      состояние ошибки с кнопкой «Повторить».
- [ ] Рассылка: предпросмотр приходит от `POST /api/v1/notifications/preview`
      только по кнопке;
      отправка — один `POST /api/v1/notifications` с заголовком
      `Idempotency-Key`; повторное нажатие после ошибки сети уходит с тем же
      ключом.
- [ ] История доставок: в запросе `$filter`, `$orderby=createdAt desc`,
      `$top`, `$skip`; текст доставки запрашивается только по кнопке.
- [ ] Объявление: публикация — один `POST /api/v1/announcements` после
      подтверждения; при категории с почтой — опрос `…/email-run`, пока
      статус не завершён.

## 5. Обновление

Новая версия — это замена папки целиком. Файлы подключения остаются.
Изменения между версиями — в `CHANGELOG.md` кита.
